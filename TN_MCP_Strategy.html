What Is MCP — Model Context Protocol

A standard that lets AI assistants connect directly to data sources and take actions on behalf of users.

Think of MCP as a universal plug socket. AI assistants — like Claude, ChatGPT, Copilot — are the devices. FE fundinfo data is the electricity. MCP is the socket that connects them.
Without MCP
An asset manager wants to know how their fund performed on Trustnet last month.

They email their account manager. The account manager manually pulls a report. It takes 2–3 days. The data is already stale by the time it arrives.
With MCP
An asset manager's AI assistant connects to the FE fundinfo MCP server. Their analyst types a question in plain English. The answer comes back in seconds — live data, no account manager needed.
What Changes
FE fundinfo data becomes machine-readable and AI-accessible. Asset managers don't need a portal login. Their AI tools query fundinfo data directly — just like a human would, but instantly.

Phase 1 — 5 MCP Tools

Five tools in the first build. Each tool answers a specific question an asset manager's AI agent would ask.

get_fund_details
Returns fund name, ISIN, AUM, currency, domicile, launch date, fund group and legal structure for a given ISIN and market.
get_fund_documents
Returns list of available documents — factsheets, KIDs, prospectus, annual reports — with download links filtered by market and language.
get_fund_performance
Returns NAV history and performance data for a given fund and date range.
get_nexus_mi
Returns Trustnet factsheet view counts and IFA engagement data for a fund — filtered to the authenticated client's funds only.
get_fundswire_articles
Returns Fundswire articles related to a fund or fund group — titles, summaries and publication dates.
Phase 2 — Coming Later
Share of research by sector. Peer comparison. Scheduled MI exports. Crown Rating history. IFA engagement trends.
Every tool response is filtered by the authenticated client's entitlements. An asset manager can only query their own funds. No cross-client data is ever returned.

How It Works — Technical Architecture

Built on existing FE fundinfo infrastructure. No new data stores. No new APIs. Just a new connection layer.

Asset Manager AI Agent
↓ MCP protocol (SSE)
FE fundinfo MCP Server — Cloudflare Workers (serverless)
↓ authentication + entitlement check
Lightning API — fund data, documents, performance
Fabric Gold Layer — Nexus MI, share of research
↓ structured JSON response
AI agent formats answer and presents to user
Cloudflare Workers
Serverless — no servers to maintain. No cost approval needed. Sagi's Feeds MCP server already deployed here. Scales automatically. Global edge network — fast response times for asset managers worldwide.
Lightning API
Already live at lightning.fundinfo.com. Documented via Swagger. Provides fund details, documents and performance data. MCP server queries this API directly — no new data pipeline needed.
Fabric Gold Layer
Microsoft Fabric gold layer — stable, maintained, DR-protected. Confirmed by Giles: "it will forever be available." Contains Nexus MI data — factsheet views, IFA engagement, share of research. MCP server queries via API.
