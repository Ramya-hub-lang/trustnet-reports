What Is MCP — Model Context Protocol

A standard that lets AI assistants connect directly to data sources and take actions on behalf of users.

Think of MCP as a universal plug socket. AI assistants — like Claude, ChatGPT, Copilot — are the devices. FE fundinfo data is the electricity. MCP is the socket that connects them.
Without MCP
An asset manager wants to know how their fund performed on Trustnet last month.

They email their account manager. The account manager manually pulls a report. It takes 2–3 days. The data is already stale by the time it arrives.
With MCP
An asset manager's AI assistant connects to the FE fundinfo MCP server. Their analyst types a question in plain English. The answer comes back in seconds — live data, no account manager needed.
What Changes
FE fundinfo data becomes machine-readable and AI-accessible. Asset managers don't need a portal login. Their AI tools query fundinfo data directly — just like a human would, but instantly.

MCP Tools — Phase 1 (Public) and Phase 2 (Token)

Phase 1 tools use public data — no token needed. Phase 2 tools use sensitive MI data — token required, filtered to client's own funds only.

🔓 Phase 1 — Open Access — No Token Required
get_fund_details
Returns fund name, ISIN, NAV, fees, charges, AUM, currency, domicile, launch date, fund group and legal structure. Public — free on fundinfo.com.
get_fund_documents
Returns KIDs, PRIIPs, factsheets, prospectus, annual reports with download links filtered by market and language. Public — free on fundinfo.com.
get_fund_performance
Returns daily NAV, prices and performance history for a given fund and date range. Public — free on fundinfo.com.
get_fundswire_articles
Returns Fundswire articles related to a fund or fund group — titles, summaries and publication dates. Public content.
get_crown_rating
Returns Crown Rating for a fund — FE Crown Rating score, rating date and methodology. Public — visible on fundinfo.com. Unique to FE fundinfo.
🔐 Phase 2 — Token Required
get_fund_engagement
Returns user engagement data for the authenticated client's own funds — view counts, document downloads, subscriber notifications. Subscription data — token required.
get_distribution_intelligence
Returns distribution partner access data for the client's own funds — which markets and channels are accessing their fund data. Token required. Own funds only.
get_share_of_research
Returns aggregated share of research data for the client's own funds vs sector. No firm names. Token required. Phase 2 build.
✗ User engagement — subscription only
Cross-client data — any data about other asset managers' funds or their engagement. Server-side block. Never returned in any response.
Phase 1 tools return public data only — already visible on fundinfo.com. Phase 2 tools require a token issued by FE fundinfo and return only the authenticated client's own data. Fabric responses are filtered server-side before any data is returned to the client.

Security — MCP-Specific Risks and Mitigations

MCP introduces a new attack surface beyond standard API security. Based on OWASP MCP Top 10, NSA guidance (May 2026) and Wiz Research (Jun 2026). These are the real risks — and how we address each one.

The honest position — same as Bloomberg and Refinitiv
No data API — Bloomberg, Refinitiv, Morningstar — claims zero leakage risk. What they claim is commercially acceptable risk with full detectability. FE fundinfo takes the same position. Phase 1 uses public data only — no sensitive data involved. Phase 2 goes live only when every security layer is in place and independently pen tested.

⚠️ MCP-Specific Risks — New Attack Surface
Prompt Injection / Tool Poisoning
OWASP MCP Top 10 — #1 risk
Malicious instructions embedded in tool descriptions hijack the AI agent's behaviour before any user action. Confirmed in real breach — April 2026 Invariant Labs demonstration.
✓ Mitigation: Tool descriptions hashed at deployment. Verified on every request. Any change = blocked. No user-supplied tool definitions accepted.
Confused Deputy Attack
MCP server manipulated into unauthorised actions
An attacker influences model inputs to redirect the MCP server's elevated privileges — without authenticating directly. Possible when tool scopes are too broad.
✓ Mitigation: Per-tool OAuth scopes. Deny-by-default. Each tool only has permission to do exactly what it needs — nothing more.
Token Passthrough / Cross-Server Reuse
Credential issued for one system reaches another
Forwarding tokens between services — instead of issuing new scoped tokens — allows a compromised intermediate to reuse credentials against unintended systems.
✓ Mitigation: OAuth 2.1 token exchange (RFC 8693). New token issued per downstream call. Short-lived — 15–60 min expiry. Never forwarded.
Unverified Task Propagation
NSA MCP guidance — May 2026
Tasks passed between MCP servers without validating origin or scope — leading to overreach, context leakage or unintended downstream tool activation.
✓ Mitigation: No multi-hop server connections. FE fundinfo MCP server is a single controlled endpoint. No task propagation between servers.

How It Works — Technical Architecture

Built on existing FE fundinfo infrastructure. No new data stores. No new APIs. Just a new connection layer.

Cloudflare Workers
Serverless — no servers to maintain. No cost approval needed. Sagi's Feeds MCP server already deployed here. Scales automatically. Global edge network — fast response times for asset managers worldwide.
Lightning API
Already live at lightning.fundinfo.com. Documented via Swagger. Provides fund details, documents and performance data. MCP server queries this API directly — no new data pipeline needed.
Fabric Gold Layer
Microsoft Fabric gold layer — stable, maintained, DR-protected. Confirmed by Giles: "it will forever be available." Contains subscription data — user engagement, distribution intelligence, share of research. MCP server queries via API for Phase 2 token holders.

Build Plan — Public First, Then Tokenised

Phase 1 is open access — public fund data, no token needed. Phase 2 is gated — subscription data requires a token issued by FE fundinfo. Cross-client data is never exposed at any phase.

No token required. Any asset manager can connect.

✓ Share of research — own funds only
✓ Crown Rating intelligence — premium tier
✗ Cross-client data — never exposed

FE fundinfo controls who gets a token and what they see.
Two separate concerns — both addressed: 1. Data leakage — answered by tokenisation. Every client connects with a token scoped to their own funds only. Schroders cannot see Fidelity's data. No cross-client data is ever returned. This applies to AI agents too — Claude, Copilot, ChatGPT are just clients. They can only see what the token permits. No AI agent gets special access. 2. Subscription data — gated by Phase 2 token. User engagement data — who viewed which fund, download counts, distribution intelligence — is private. Only accessible with a valid Phase 2 token scoped to the authenticated asset manager's own funds. No cross-client data ever returned. Every Phase 2 query is logged with timestamp, token and data returned for full audit trail.
